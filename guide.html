ProTrack user guide

Construction productivity intelligence: from the daily site report to management decisions, invoices and cash.

ProTrack turns what the site records every evening into productivity, earned value, forecast cost, invoiceable value and early warnings, and it measures the people who feed it. Its principle is one sentence: quantity alone is progress; quantity together with the resources that produced it is productivity. Everything follows from capturing both, once, at site.

2. How the application works

ProTrack is a single chain. Each link is owned by one role, and every later link depends on the ones before it.

  1. Set up. The super admin creates the project, users and access, trades and salary rates, milestones including TCC, PAC and FAC, and the contract payment terms.
  2. Baseline. The planning engineer imports the P6 schedule. ProTrack reads activities, WBS, dates, labour hours, material quantities, the price weighting resource and the trade mix, then runs the DCMA 14-point check.
  3. Budget and purchase orders. The costing engineer downloads the costing template, pre-filled with every activity ID, adds budget quantity, unit, unit rate, cost and manhours, and uploads it. He then enters each subcontractor's purchase order for the project, with its rates.
  4. Daily reporting. Every working day the foreman or site engineer reports, per activity, the quantity executed and the crews that produced it: own labour, subcontractors with their trades, and equipment.
  5. Review and approval. The site engineer reviews what the foreman submitted; the site manager approves it the same evening. The project manager can do either. Nothing counts until it is submitted, and only approval closes the audit trail. Every step is timed.
  6. Weekly update. The planning engineer updates design and procurement by milestone from one Excel file, until those phases are complete.
  7. Invoicing. The costing engineer uploads the invoice register weekly: invoice number, amount, submitted, approved and collected, including the advance.
  8. Analysis. ProTrack calculates productivity, earned value, EAC, manpower forecasts, unit rates, reconciliation and invoiceable value against the contract terms, and raises early warnings.
  9. Oversight. Management reads the executive summary, the reports and RASA; the performance scorecards show who is keeping the chain alive, and reminders chase the gaps.
Why the order mattersCosting matches on activity IDs, so it cannot come before the baseline. Productivity needs the planned rate, so it cannot come before costing or the P6 labour loading. Invoiceable value needs the price weighting and the payment terms. If a screen reads zero, the link before it is usually missing.

Approval matrix

The super admin decides, project by project, who reviews and who approves. In Settings → Approval matrix each project lists its foremen and site engineers, with a choice beside each name:

  • Foreman → site engineer who reviews his reports on that project
  • Site engineer → site manager who approves the reports he has reviewed on that project

Only people with access to that project are offered. Someone working on several projects is assigned separately on each, so the chain follows the site team of each project. Anyone left unassigned has that step done by the project manager, and the project heading says how many are unassigned.

Approval email

The moment a report is approved, ProTrack emails a summary to everyone with access to that project in the chosen roles: by default site engineers, site managers, project managers, portfolio managers, planning and costing engineers, executives and super admins. Site engineers and site managers receive only the reports they reviewed or approved. Recipients are blind-copied.

The email carries the project, date, discipline and foreman; activities, manpower, manhours and productivity; each activity's quantity today, percent complete and index; anything below 85% productivity; site remarks; who prepared, reviewed and approved it and how long each took; and an Open in ProTrack button that goes straight to the report after sign-in.

The super admin chooses the roles, or switches it off, in Settings → Email, which also lists every email with its recipients, status and a preview. Sending needs the mail function set up on the server once; until then emails are prepared and listed but not sent.

Import centre and controlled uploads

Four files feed ProTrackAI: the invoice register and costing file (costing engineer or project manager), the P6 baseline and the weekly engineering and procurement progress (planning engineer). Every one goes through the same five steps.

  1. File check. Only Excel (.xlsx, .xls), CSV, Primavera XER or P6 XML, up to 10 MB. Workbooks with macros (.xlsm) are refused before they are read; formulas and macros are never run.
  2. Row checks. Each row is checked: the activity or invoice exists and belongs to this project (a Project column, if present, must match), the currency is SAR (if a Currency column is present), dates are real dates, numbers are numbers, and nothing appears twice. A refused row shows its reason and its row number in the sheet.
  3. Preview and reconciliation. Before anything is saved you see the rows in the file, accepted, refused and warnings, and for money the total in the file, the total accepted and the difference. Download exception report gives every refused row and warning as a spreadsheet to send back for correction.
  4. Acknowledge. If any row is refused, the Apply button stays grey until you tick that you have reviewed the refused rows and want to load only the accepted ones. Your name and an optional note are recorded with the batch. The server enforces this too.
  5. Save in one piece. Everything is saved in one transaction. If anything fails half way, nothing is saved and the previous data stays exactly as it was. A file with no valid row never empties the register. The same content loaded twice changes nothing the second time.

The Import centre

Imports & Integrations → Import centre lists every batch for your projects: batch number (IMP-000123), type, project, file, rows accepted, total in the file and accepted, result, who and when. Filter by type or by result (committed, with a difference, failed). Click a batch for the full record: source system, period, currency, file fingerprint (SHA-256), size, reconciliation, who accepted a difference and their note, commit status, error, retry and audit reference, with its exception report. A failed attempt stays listed; when the same file later loads successfully, both show the link (Failed, retried and Retry of).

Planning, costing, project managers, executives and regional and portfolio managers see the Import centre; site roles do not. SAP: SAP ECC Excel exports will be added here once a sample export and the Finance rules are agreed; any direct SAP or S/4HANA connection stays switched off until IT, SAP, Cybersecurity and Finance approve it.

6. Step by step, by role

Foreman — every working day, about five minutes

  1. Sign in on your phone. You see daily reports, new report and your own performance, for your projects only.
  2. New report. Date and project are filled in; choose yourself as foreman.
  3. Work location, work type, WBS, activity. Each choice narrows the next, so the activity list is short.
  4. Quantity executed today — the total placed on that activity, including anything done by subcontractors.
  5. Own labour — trade, workers, regular and overtime hours. The usual crew is pre-filled; correct what differs.
  6. Subcontractor — choose the company once, enter the quantity they executed, then Add trade for each of their trades with workers and hours. A second company is a second block.
  7. Equipment — type, units, hours.
  8. Add another activity for everything else your crews did today.
  9. Check the productivity panel. It shows the combined index and, where a subcontractor worked, your own figure and theirs separately. An amber line means a subcontractor quantity has no hours.
  10. Remarks and photos — delays, access, weather, instructions.
  11. Submit. It goes to your site engineer for review, then your site manager for approval.

A clock at the top of the form starts when you open it and stops when you save or submit; it carries on if you return to a saved draft. Time with the app in the background is not counted.

Example: 80 m³ poured, 30 of it by a subcontractorEnter 80 as the quantity. Add your own crew. Add the subcontractor with quantity 30 and each of his trades with their hours. ProTrack derives your share as 50 and counts both crews' hours in the index.

Site engineer — review every foreman's report, daily

  1. Daily reports → Submitted. Open each report the foremen sent; a timer runs while it is open.
  2. Mark as reviewed once quantity and crews are right, or return with comments. It then goes to the site manager assigned to you on that project. You only see the Review button on reports from foremen assigned to you.
  3. Daily reports → Draft. Nothing should stay in draft overnight.
  4. Check quantities against survey or measurement, and crews against the gate count.
  5. Correct and submit. Your edits are logged.
  6. Deal with returned reports the same day; the manager's comment is in the audit trail.
  7. Weekly: Reports → Productivity and the Manpower histogram for your trades; Executive summary → Project view for bottlenecks and foreman performance.

Site manager — approve every reviewed report, the same day

  1. Daily reports → Reviewed. You can approve those reviewed by the site engineers assigned to you on each project.
  2. Open each one. A timer runs while it is open; the time you take is recorded.
  3. Approve, or return or reject with a comment.
  4. Performance shows your foremen and site engineers, and which projects have gone quiet; Reports → Report handling time shows how long each person takes.
  5. Presentation builds the site progress deck for your meeting.

Project manager — oversight, commercial, monthly invoice

  1. Daily reports. Site managers approve day to day; step in to review or approve when they are absent. Three checks: is the quantity credible for that crew, was that crew on site, is the index explainable.
  2. Baselines → Costing file, Invoice register, Purchase orders are open to you for your projects.
  3. Monday: Dashboard, Executive summary → Project view, Reports → Early warnings, Manpower histogram, EAC.
  4. Monthly: make sure an invoice goes in every month until invoicing reaches 80% of the contract value. Performance → Project managers shows your monthly invoicing record; months with nothing submitted are listed by name.
  5. Before the review meeting: Presentation → pick the slides → download.

Planning engineer — at award, every week, at each revision

  1. Schedule the programme in P6 (F9) before exporting. An unscheduled export carries no float, and DCMA cannot assess float.
  2. Baselines → project → Original baseline → load the XER.
  3. In the preview: work location level (for a line, the section level), class level, price weighting resource, WBS branches to monitor and classes to import. Read the warning if no IDs match.
  4. Import, then read the DCMA check on the same page and fix what fails in P6.
  5. Map P6 labour resources to trades, once per project; create any missing trades.
  6. Tell costing the baseline is in.
  7. Every week until design and procurement are complete: Weekly update → download template → fill milestones and dates → upload → preview → apply. Then export the P6 progress update from Reports.
  8. At a revision: load a revised or recovery set; use Measure against to report on it. Wrong file? Undo this import.

Costing engineer — at award, at each budget revision, every week

  1. Baselines → project → Costing file → Download template. It carries every activity ID.
  2. Fill budget quantity and unit (required), unit rate and cost, and manhours if the costing budget differs from P6. Leave the gang code blank unless you use standard crew codes.
  3. Upload, read the preview: matched, rejected, missing, and manhour differences over 25%. Fix rejected rows at source and re-upload rather than accepting partial files.
  4. Purchase orders — Baselines → your project → Subcontractor purchase orders. For each subcontractor working on the project: choose the company, or New subcontractor to add one; enter PO number, basis (Measured or Manpower supply), date and value; Add purchase order.
  5. Rates. Click the purchase order to open it. For a measured PO add a rate per activity of this project, in its unit; for manpower supply, a rate per trade per manhour. Give each rate its effective date; a revision is a new rate with a later date, never an edit.
  6. Check cost to date. The table shows each PO's cost so far from the daily reports and its share of the PO value, so an overrun shows before the subcontractor's invoice does.
  7. Every week: Invoice register → upload the whole register: invoice number, date, type, amount, submitted, approved, collected. The advance goes in as its own row.
  8. Monthly: Reports → Unit rate analysis, Quantity reconciliation, Budget manhour reconciliation, Invoicing and collection.

Executive, regional and portfolio managers — weekly scan

  1. Executive summary. Customise it once: choose tiles such as Under-billed, Outstanding collection; group by region or sector; pick columns.
  2. Critical projects, worst first, then open the worst in Project view.
  3. Performance → Reporting compliance. Anything in red has gone quiet; press Notify team.
  4. Performance → Project managers for approval backlog and monthly invoicing; Planning and Costing tabs for schedule quality and timeliness.
  5. Ask RASA what the screen does not answer.

Super admin — setup, then as things change

  1. Regions, cities, sectors with their managers.
  2. Trades and rates: basic salary, hours per month, loaded factor, effective date.
  3. Project: code in any format, sector, region, city, dates, value, type, budget manhours source.
  4. Users and access: role and projects or regions for each person, including site managers. Someone on two projects gets access to both.
  5. Project team: project manager, site engineer, foremen.
  6. Milestones with TCC, PAC, FAC, and the EOT claim.
  7. Payment terms: per phase the progress cap and up to two milestone releases; separate retention only if the contract has one; advance and its recovery rate.
  8. Settings → Approval matrix: for each project, choose the site engineer who reviews each foreman, and the site manager who approves each site engineer. Repeat whenever the site team changes.
  9. Settings → Email: choose who receives the approval summary.
  10. Settings → System, once after installing version 2.5: move anything people entered in their browsers to the server (see Moving browser data to the server), and download a server backup every week.
  11. Settings → System: check the version, and choose the date basis: demo (fixed 22 Sept 2026) for demonstrations, live (today) for real work. Each keeps its own data in the browser. Once real data is on the server, set DATE_MODE: 'live' in config.js so nobody can switch it by mistake.
  12. Settings → Role access: for site engineers and site managers, tick the reports they may open and set the tiles, breakdown and columns of their executive summary. Cost and billing are never offered.
  13. Hand purchase orders to costing. Each project's costing engineer keeps its subcontractor POs on the Baselines page. Settings → Subcontractors still shows every company and PO across all projects, for review or correction.
  14. Hand over to planning and costing. Afterwards: leavers set inactive, pay rises as new dated rates, wrong baselines undone, change log reviewed.

7. How performance is measured

Every scorecard is calculated from data the person already enters. No score depends on anyone's opinion. Unless stated, windows are the last 30 days of submitted or approved reports.

Foreman score, out of 100

Score = min(PI, 1.2) ÷ 1.2 × 60 + approval rate × 25 + (1 − rework rate) × 15
  • PI — productivity index of his reports: earned manhours ÷ actual manhours, capped at 1.2 so a single freak day cannot dominate.
  • Approval rate — approved ÷ (approved + rejected).
  • Rework rate — reports returned or rejected ÷ reports submitted.

Site engineer score, out of 100

Score = compliance × 30 + timeliness × 25 + approval rate × 20 + min(PI, 1.2) ÷ 1.2 × 25
  • Compliance — working days with a report ÷ working days in the window.
  • Timeliness — reports not flagged late ÷ reports.
  • Approval rate and PI as for foremen, for the whole project.

Project manager KPIs

KPIDefinition
Approved, rejected, returnedCounts over 30 days across his projects
PendingSubmitted or reviewed, not yet approved; red when the oldest is over 2 days
Average days to approveMean of (approval date − submission date) for approved reports
SPI, CPI, cost varianceEV ÷ PV, EV ÷ AC, EV − AC across his projects
Productivity, overtimePI and overtime hours ÷ total hours
Under-billedInvoiceable − invoiced
Collection pendingApproved − collected
Monthly invoicingMonths with an invoice ÷ months due
Months due = calendar months from project start up to the month when cumulative invoiced reaches 80% of contract value, or up to this month if 80% has not been reached.
Months invoiced = months in that window with at least one invoice, excluding retention releases.

Also shown per project: longest gap (longest run of months with nothing submitted), days since last invoice (red over 45), invoiced as a share of contract value, and the months missed by name. After 80%, milestone invoices at TCC and FAC take over and the monthly requirement stops.

Planning engineer score, out of 100

Score = (DCMA pass rate × 0.5 + weekly update compliance × 0.5) × 100
  • DCMA pass rate — checks passed ÷ checks assessable, averaged across his projects' imported XERs (section 8).
  • Weekly update compliance — weeks with a design and procurement upload ÷ weeks elapsed, counted from the first engineering or procurement activity until all of them are complete; after that no update is required.
  • Where either part cannot be measured yet, it counts as 50% so a new project neither rewards nor punishes.

Costing engineer score, out of 100

Score = upload quality × 40 + costing coverage × 20 + timeliness × 40
  • Upload quality — 1 − (rejected rows + ½ × flagged rows) ÷ rows uploaded, across all costing uploads.
  • Costing coverage — activities with a costing row ÷ activities in the baseline.
  • Timeliness — weeks in the last twelve with an invoice register upload ÷ weeks (fewer for a newer project).

Reporting compliance score, by project, out of 100

Score = 100 − 5 × missing report days − min(20, 3 × age of oldest pending report in days) − 10 if weekly update overdue − 5 if invoice register overdue
  • Missing report days — working days in the last 14 (Fridays excluded) with no submitted report.
  • Weekly update overdue — more than 9 days old, where the project has design or procurement activities.
  • Invoice register overdue — more than 9 days old, where payment terms are set.
  • Issues are graded: no report for more than a day is High; more than two missing days, an approval backlog, or an overdue weekly update is Medium; an overdue register is Low.

Scores are coloured green at 85 and above, amber from 60, red below 60.

Report handling time

Reports → Time spent preparing, reviewing and approving daily reports. Per person, over 30 days: reports handled, average, median, fastest, slowest, time per activity line and total, for each step.

Preparation = time the new report form is open, from opening to save or submit, summed across draft sessions
Review = time a submitted report is open with the review action available, until the site engineer acts

9. Formula reference

Productivity

Planned rate = budget quantity ÷ budget manhours
Earned manhours = quantity executed ÷ planned rate
Actual manhours = own workers × (regular + overtime hours) + subcontractor workers × hours
Productivity index (PI) = earned manhours ÷ actual manhours — green above 100%, amber 90–100%, red below 90%
Own quantity = quantity executed − subcontractor quantities; own and subcontract PI are shown separately

Earned value

Budget value per activity = costing budget cost, else P6 price weight, else manhours × blended rate
SPI = EV ÷ PV · CPI = EV ÷ AC · SV = EV − PV · CV = EV − AC
EAC = BAC ÷ CPI, or AC + (BAC − EV) ÷ (CPI × SPI) · VAC = BAC − EAC · TCPI = (BAC − EV) ÷ (BAC − AC)

Cost

Trade hourly rate = basic salary ÷ hours per month × loaded factor, taken from the rate effective on the report date
Own labour = workers × (regular + 1.5 × overtime) × trade rate
Measured subcontract = quantity × PO unit rate · Manpower supply = workers × hours × PO manhour rate

Planning

Planned headcount = baseline daily quantity ÷ planned rate ÷ 8, split by the P6 trade mix
Forecast headcount = planned headcount × (planned rate ÷ actual rate over 21 days) · To mobilise = forecast − current

Unit rates and reconciliation

Actual cost per unit = executed cost ÷ quantity executed, split into own, rental and subcontract
Carried in + own + rental + subcontract = executed · Executed + remaining = scope

10. Billing and collection

Invoiceable value

Earned price per phase = phase price × price progress, where price comes from the P6 weighting resource
Billable per phase = min(earned price, phase price × progress cap) + releases whose milestone is achieved
Net invoiceable = Σ billable − separate retention (if any) + retention released − advance recovered

Example: construction 80% on progress, 10% at TCC, 10% at FAC. At full progress before TCC, 80% is billable. Set separate retention to zero unless the contract deducts it on top of the phase split. Advance recovery is a percentage of each invoice and stops once the advance is repaid. Blank or zero? A blank progress cap means 100%; 0 means nothing is billed on progress, only at the milestone releases. A blank retention cap means no cap; a retention percentage with a 0% cap is refused, because nothing would be held. Terms saved before version 2.4 keep their earlier meaning, where 0 was read as no cap.

Backup and restore

  1. Settings → System → Download server backup (signed in to the server): one file with every project you can see, its activities, daily reports with their complete history, invoices, approval matrix and import records. The super admin should do this every week and keep the files somewhere safe.
  2. Download browser backup: everything this browser holds, including anything still waiting to move to the server.
  3. Restore a backup (demo mode): choose the file. ProTrackAI first shows what is in this browser and what is in the backup, side by side. Only when you press Restore this backup and confirm does it replace the data, and a backup of what was there downloads first, so a restore can itself be undone.
  4. Signed in to the server, a browser backup is never written over server data. The super admin can load one to add its reports to the list waiting to move.

Moving browser data to the server

Before version 2.5, daily reports, baselines, costing and invoices were saved in each person's browser. When someone signs in to version 2.5, anything their browser holds for a server project is set aside, untouched, and listed in Settings → System → Browser data waiting for the server.

  1. Sign in as super admin on the computer where the data was entered. If it was entered on someone else's computer, ask them for a browser backup (Settings → System → Download browser backup) and load it with Load a browser backup.
  2. Check the list: for each project, the number of activities, reports and invoices waiting.
  3. Press Move to server and confirm. A browser backup downloads first. Then, in this order: activities the server does not have yet, costing, invoices (only if the server has no register for that project), and daily reports with their full history.
  4. Read the result. Each step shows ✓ or ✗, and a reconciliation table compares the browser and the server: activities, budget manhours, reports, approved reports, quantity and manhours reported, invoices and their total. Every row should say Match.
  5. A report the server already has (same number) is skipped, never overwritten. A report whose activity is missing, or that clashes with a report for the same foreman and date, is refused and listed with the reason. Pressing Move again is safe: nothing is created twice.
  6. Re-assign the approval matrix in Settings → Approval matrix: assignments made in a browser before 2.5 referred to browser accounts and do not carry over.

13. Rules the system enforces

  • Only submitted, reviewed and approved reports count; drafts and rejected reports never reach a dashboard.
  • Construction progress only from daily reports; engineering and procurement only from the weekly update.
  • Price only from P6; cost only from the costing file. Each project names which file owns budget manhours.
  • Rates and PO rates are dated; a change never restates a filed report.
  • One purchase order per subcontractor per project; a second one for the same company is refused.
  • Re-baselining moves the plan, never earned progress; every import can be undone.
  • A subcontractor's quantity is entered once per company; all their trades' hours count.
  • Foreman submits, site engineer reviews, site manager approves, as assigned in the approval matrix for that project; the project manager covers anyone unassigned.
  • Every approval emails a summary to the project's stakeholders.
  • Site roles never see cost or billing, and their executive view is set by the super admin.
  • Rejecting or returning needs a comment; every change is logged with a name and time.
  • On the server: a report is saved, reviewed and approved only through ProTrack's server functions. Writing to the tables directly is refused.
  • On the server: a foreman always reports under his own name, can edit only his own drafts, and cannot change a report once submitted.
  • On the server: an approved report cannot be changed or deleted by anyone, and a project that has approved reports cannot be deleted.
  • On the server: report history and the change log can only be added to. Each history entry is sealed with the one before it, so any alteration is detectable.
  • On the server: one report per foreman per day; no future dates; the same activity once per report; no more than 24 hours a day per worker.
  • On the server: loading the same costing file, invoice register or baseline again changes nothing; a failed row is refused and listed, never half-applied.
  • Every upload is a numbered batch with the file's fingerprint; refused rows must be acknowledged by name before the rest is saved, and a failed upload never changes the last good data.
  • Only Excel, CSV, XER and P6 XML files up to 10 MB are accepted; workbooks with macros are refused.

14. FAQ and troubleshooting

I cannot see Review or Approve on a report

The approval matrix routes each report to one site engineer and one site manager per project. If it is not assigned to you, the button does not appear. The route is shown at the top of every report; the super admin changes it in Settings → Approval matrix.

A report went to the project manager instead of a site engineer

That foreman, or his site engineer, has no assignment on that project. The project heading in Settings → Approval matrix shows how many are unassigned.

Settings → Email says "Demo: not sent"

Emails are prepared and listed, but the mail function is not set up on the server yet. Follow EMAIL-SETUP.md once.

All my figures look out of date

The app may be in demo mode, which measures everything at 22 Sept 2026. Settings → System shows the mode; switch to live for today's date.

The timer shows zero or stops

It pauses while the app is in the background and resets if you leave the form without saving. Save as draft to keep the time.

Productivity reads very high

A subcontractor quantity is entered without their workers and hours. The form warns in amber.

DCMA shows float as not assessed

The XER was exported without scheduling. Press F9 in P6, then export again.

A project shows zero everywhere

No baseline yet, or the costing file and labour loading are both missing, so there is no planned rate.

Invoiced is higher than invoiceable

Either invoicing is ahead of certified progress, or the payment terms or price weighting are not set. Check the terms on the project.

A subcontractor line says "estimated"

That company has no purchase order on the project, or no rate for that activity or trade. The project's costing engineer adds it on the Baselines page.

"Invalid API key" at sign-in

The key in config.js is incomplete or from another project. Copy the anon key again with the copy icon.

"The server refused this" when reviewing or approving

The server checks the approval matrix itself. Only the site engineer assigned to that foreman on that project can review, and only the site manager assigned to that engineer can approve; the project manager can do both. Ask the super admin to check Settings → Approval matrix.

"This foreman already has a report for that date"

Open the existing report and edit it instead of creating a second one.

"This is the same file as the last one loaded, so nothing changed"

The server recognised the file. If you meant to load corrected figures, check you chose the corrected file.

Undo import or Remove baseline says it is not available

On the server a baseline is never removed, so report history always keeps its activities. Import the correct file again; activities are matched by ID and updated.

An amber bar says the server data could not be loaded

Your connection or the server was unavailable. Press Try again. Anything you change is still sent to the server, which checks it; nothing is saved only in the browser.

I cannot sign in with a demo account

Demo accounts are switched off on a site connected to the server. Use your work email; the super admin creates accounts in Supabase. For a demonstration, open the demo page (demo.html, linked from the sign-in page), where the demo accounts work on sample data.

The Apply button stays grey

Some rows were refused. Read the reasons (or download the exception report), then tick the box confirming you want to load only the accepted rows. Or fix the file and upload it again.

"The server refused some rows"

The server checks every row again. If it refuses a row the app accepted, the preview shows its message; tick the box to load the rest, or fix the file.

An upload shows as Failed in the Import centre

Nothing from it was saved and your previous data is unchanged. Open the batch for the reason, fix the cause, and upload the same file again: it shows as a retry of the failed attempt.

Delete or undo did nothing

You are on an old version. Upload the latest index.html and press Ctrl+F5.
